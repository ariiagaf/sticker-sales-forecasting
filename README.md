# Sticker Sales Forecasting

ML project for the Kaggle "Forecasting Sticker Sales" competition
(Playground Series S5E1). The task is to predict daily `num_sold` for
90 (country, store, product) time series covering 2010-2016 (train) and
2017-2019 (Kaggle test). Metric: MAPE.

## Setup

Use Python 3.11 or newer (pandas 3.x requirement). Dependencies are pinned
in `requirements.txt` (versions verified by running the full pipeline, tests
and notebooks).

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Download the Kaggle competition data and place it in `data/`:

```
data/train.csv
data/test.csv            # not needed for the experiments, only for Kaggle submissions
```

`data/*.csv` is git-ignored, so this step is required after every fresh clone.
Source: https://www.kaggle.com/competitions/playground-series-s5e1/data

## Validation scheme (used by ALL models)

Random splitting is **not** used (it would leak the future). Train data covers
2010-2016 and is split into disjoint roles:

```
fold_1_2013: train 2010-2012 -> validate 2013
fold_2_2014: train 2010-2013 -> validate 2014
fold_3_2015: train 2010-2014 -> validate 2015
test_2016:   train 2010-2015 -> test 2016   (independent, final evaluation only)
```

- **Validation (2013-2015)** is used for choosing hyperparameters and models.
- **Test (2016)** is used only for the final evaluation: each final model is
  fitted once on 2010-2015 and scored once on 2016. Test results are never
  used to tune or select anything.
- The scheme is enforced in code: `expanding_window_splits` rejects validation
  years that overlap the test year and removes test rows from its input;
  `tune_catboost` raises if it receives test-year data.
- Baselines and CatBoost use the same splits, the same rows (checked by
  `check_same_evaluation_rows`) and the same `mape()`.

```python
from src.validation import split_development_test, expanding_window_splits

dev_df, test_df = split_development_test(df)         # dev: < 2016, test: 2016
for train_part, val_part in expanding_window_splits(dev_df):
    ...
```

## Baselines

`src/baselines.py`: `group_median`, `seasonal_naive_last_year`, `ridge_calendar_one_hot`.

`seasonal_naive_last_year` forecasts each date with the actual sales of the same
date one year earlier, taken from the training data only, and falls back to the
group (country, store, product) median when that value does not exist. Since
every evaluation window is one year long, the value always comes from the
previous year's real sales (the share of forecasts that really use last year
vs. the fallback is saved to `results/seasonal_naive_coverage.csv`).
For a window longer than one year the later years would silently use the
fallback, which is why a multi-year "long-horizon" window is not used as the
evaluation scheme.

```bash
python -m src.baselines
```

## Model

CatBoost (`src/model.py`) with one interface and two target modes:

```python
model = fit_model(train_df, params=None, target_transform="none")   # catboost_raw
model = fit_model(train_df, params=None, target_transform="log1p")  # catboost_log
pred = predict_model(model, features_df)   # always on the original num_sold scale
```

| model | target | hyperparameters |
|---|---|---|
| `catboost_raw` (v1) | `num_sold` | default |
| `catboost_log` (v2) | `log1p(num_sold)` | default |
| `catboost_raw_tuned` (v3) | `num_sold` | best on validation |
| `catboost_log_tuned` (v3) | `log1p(num_sold)` | best on validation |

The search grid is in `src/tuning.py`; all candidates and their validation
scores are saved to `results/tuning_results.csv`. The final CatBoost model is the
one with the lowest mean **validation** MAPE. Every model is re-trained from the
code (nothing is loaded from old CSV files).

## Reproducing the results end-to-end

One command (about as long as the tuning grid takes to run):

```bash
python -m src.pipeline --train-path data/train.csv --readme README.md
python -m src.make_report_draft          # numbers for the report, from results/
```

or run the notebooks in order: `02_baselines` -> `03_model` -> `04_evaluation`.

To verify reproducibility in a clean environment (new virtualenv, tests, two
independent full runs compared, report with date / OS / versions / status):

```bash
bash scripts/clean_env_check.sh data/train.csv
```

The result is written to `results/reproducibility_check.md`.

Tests (no real data needed): `python -m pytest -q tests`

`python -m src.pipeline --quick` runs a tiny grid for smoke tests only; its numbers are not results.
